# دليل تحسين أداء الويب وتحقيق نتائج قياسية في Core Web Vitals

تعد مؤشرات أداء الويب الأساسية (Core Web Vitals) المعيار الذهبي المعتمد من قِبل Google لقياس جودة وسرعة تجربة المستخدم على الويب. إذا كان موقعك بطيئاً، فلن تخسر فقط ترتيبك في محركات البحث (SEO)، بل ستفقد جزءاً كبيراً من زوارك ومعدل التحويل (Conversion Rate).

> **القاعدة الذهبية للأداء:** كل 100 ميلي ثانية إضافية في زمن استجابة الموقع قد تكلف انخفاضاً بنسبة 1% في المبيعات، بينما تقليص وقت التحميل بثانية واحدة يزيد من تفاعل الزوار بنسبة تصل إلى 27%.

---

## 1. المؤشرات الثلاثة الرئيسية وأهدافها المستهدفة

| المؤشر | الاسم الكامل | ما يقيسه فعلياً | النتيجة الجيدة (Good) | تحتاج تحسيناً (Needs Work) | سيئة (Poor) |
| :---: | :--- | :--- | :---: | :---: | :---: |
| **LCP** | Largest Contentful Paint | سرعة تحميل أكبر عنصر مرئي بالصفحة | `<= 2.5 ثانية` | `2.5 - 4.0 ثوانٍ` | `> 4.0 ثوانٍ` |
| **INP** | Interaction to Next Paint | مدى سلاسة واستجابة الصفحة لنقر وتفاعل المستخدم | `<= 200 ميلي ثانية` | `200 - 500 ميلي ثانية` | `> 500 ميلي ثانية` |
| **CLS** | Cumulative Layout Shift | الاستقرار البصري ومقدار القفزات غير المتوقعة للعناصر | `<= 0.1` | `0.1 - 0.25` | `> 0.25` |

---

## 2. قائمة التحقق الشاملة لتحسين LCP (سرعة التحميل)

لتحقيق سرعة قصوى في تحميل العنصر الأساسي، اتبع هذه القائمة العملية:

- [x] **تفعيل ضغط الصور الحديث:** تحويل كافة الصور إلى صيغ `WebP` أو `AVIF` الحديثة لتوفير 30-70% من الحجم.
- [x] **إضافة أبعاد صريحة للصور:** تعيين `width` و `height` دائماً لمنع قفزات التخطيط.
- [x] **تحديد أولوية تحميل صورة الغلاف:** استخدام خاصية `fetchpriority="high"` لصورة الـ Hero.
- [ ] **تحسين خطوط الويب:** استخدام خاصية `font-display: swap` واستضافة الخطوط محلياً إن أمكن.
- [ ] **استخدام CDN فائق السرعة:** لتوزيع الأصول الثابتة وتقليل زمن وصول أول بايت (TTFB).

### مقارنة كود تحميل صورة الغلاف (Hero Image):

**قبل التحسين (غير محبذ):**
```html
<!-- تحميل متأخر وعرضة للقفزات البصرية -->
<img src="large-hero-banner.png" alt="بانر رئيسي">
```

**بعد التحسين (الممارسة الفضلى):**
```html
<!-- تحميل فوري ذو أولوية فائقة بصيغة حديثة مع أبعاد ثابتة -->
<link rel="preload" as="image" href="hero-banner.webp" fetchpriority="high">
<img 
  src="hero-banner.webp" 
  width="1200" 
  height="600" 
  fetchpriority="high" 
  loading="eager" 
  decoding="async" 
  alt="بانر رئيسي محسن">
```

## 3. معالجة مشاكل التفاعل واستجابة الواجهة (INP)

يقيس مؤشر INP الوقت بين نقر المستخدم على زر أو عنصر تفاعلي ووقت ظهور التحديث الفعلي على الشاشة. أكبر عائق أمام هذا المؤشر هو المهام الطويلة (Long Tasks) التي تحجز خيط المعالجة الرئيسي (Main Thread) لأكثر من 50 ميلي ثانية.

### كسر المهام الطويلة باستخدام `scheduler.yield()`:

```javascript
// تقسيم العمليات الحسابية الضخمة حتى لا يتجمد المتصفح
async function processLargeBatch(items) {
  for (let i = 0; i < items.length; i++) {
    performHeavyCalculation(items[i]);

    // إذا استغرقت الدورة وقتاً طويلاً، نترك المتصفح ليعالج نقرات المستخدم
    if (i % 50 === 0 && 'scheduler' in window && 'yield' in scheduler) {
      await scheduler.yield();
    } else if (i % 50 === 0) {
      // بديل للمتصفحات القديمة
      await new Promise(resolve => setTimeout(resolve, 0));
    }
  }
}
```

## 4. القضاء التام على القفزات البصرية (CLS = 0.00)

القفزات البصرية المزعجة تحدث غالباً بسبب:
1. إعلانات أو صور تظهر فجأة وتدفع المحتوى للأسفل.
2. خطوط ويب تتأخر في التحميل ثم تبدل حجم النص فجأة (FOIT / FOUT).

```css
/* الحل: حجز مساحة مسبقة لأي محتوى ديناميكي عبر aspect-ratio */
.media-container {
  width: 100%;
  aspect-ratio: 16 / 9;
  background-color: var(--surface-secondary);
  overflow: hidden;
}
```

## 5. الأدوات الموصى بها للقياس المستمر

1. **Lighthouse & PageSpeed Insights:** لفحص الصفحة بشكل مختبري (Lab Data).
2. **Chrome User Experience Report (CrUX):** للحصول على بيانات الزوار الحقيقيين في الميدان (Field Data).
3. **مكتبة `web-vitals` الرسمية من Google:**
   ```javascript
   import { onCLS, onINP, onLCP } from 'web-vitals';

   onCLS(console.log);
   onINP(console.log);
   onLCP(console.log);
   ```

> **ملخص:** الأداء ليس ميزة ثانوية تضيفها بعد اكتمال المشروع، بل هو خيار معماري هندسي يبدأ من كتابة أول سطر كود ويستمر طوال دورة حياة المنتج.
